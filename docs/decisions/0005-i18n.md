# 0005 — In-house typed i18n

## Problem

The app must be available in English and Brazilian Portuguese. A library would solve this, but the requirement is two locales and
a few dozen strings; the risk to avoid is untyped keys (typos that render as the key at runtime) and untranslated strings.

## Solution

A small module in `src/i18n`:

- `en.json` / `pt-BR.json` (nested). `en.json` is the source of truth: the key union `MessageKey` is derived from its shape, and
  `pt-BR.json` is assigned to that type, so a missing or renamed key fails compilation. `t('errors.retry')` is autocompleted and
  checked; dynamic keys such as ``t(`errors.${variant}.title`)`` compile only if every variant has that key.
- `translate(locale, key, params)` is a pure function: falls back to English, then to the key, and interpolates `{name}`.
- `I18nProvider` / `useI18n()` hold the locale in React state, persist it in `localStorage` (tolerating blocked storage), start from
  the stored choice or `navigator.language`, and keep `<html lang>` in sync for screen readers.

## Why this approach

Two locales do not justify `react-i18next` (bundle, config, and runtime-string keys). Compile-time key checking is a stronger
guarantee than most libraries give by default. Locale is client state, not server state, so React state is appropriate.

## Alternatives

- `react-i18next` / `FormatJS`: full ICU, plurals, lazy-loaded namespaces. Worth it with many locales or complex plural rules.
- Untyped JSON lookups: simplest, but typos surface at runtime only.

## Trade-offs

- No ICU plural/gender rules (none needed yet; `Intl.PluralRules` is available when it is).
- Both locales are bundled. Fine at this size; split by locale if strings grow substantially.
- Object-shape typing does not reject _extra_ keys in `pt-BR.json`; a test asserts identical key sets.

## How it is tested

`messages.test.ts`: identical key sets, no empty strings, fallback, interpolation, locale detection table.
`I18nProvider.test.tsx`: switching updates text and `<html lang>`, choice persists, works with storage blocked.
`routes.test.tsx`: switching language re-renders the whole shell.
